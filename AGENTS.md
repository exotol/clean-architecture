# Правила для кодинг-агентов (EVA)

**Назначение:** этот документ задаёт жёсткие правила разработки для любых AI-агентов (Cursor, Codex, и др.). Цель — **никогда не ломать работоспособность системы**, бережливое производство (LEAN), максимальная аккуратность.

---

## 1. Закон: не ломать систему

- **Перед любым изменением** убедись, что понимаешь влияние на существующие вызовы, контракты API и тесты.
- **После любого изменения** считай обязательным:
  - запуск линтеров и типизации;
  - запуск тестов (как минимум unit с покрытием).
- **Запрещено:**
  - менять публичные контракты (сигнатуры, имена эндпоинтов, форматы ответов) без явного согласования;
  - удалять или ослаблять существующие тесты;
  - отключать линтер/типы для «удобства» правки (noqa/type: ignore только по обоснованной причине с комментарием).

---

## 2. LEAN — бережливое производство

- **Минимальные изменения:** правка должна решать только поставленную задачу. Не рефакторить «заодно» без явного запроса.
- **Нет лишнего кода:** не добавлять неиспользуемые импорты, переменные, функции, зависимости.
- **Нет дублирования:** при повторяющейся логике — вынести в переиспользуемую функцию/сервис и покрыть тестами.
- **Прозрачность:** новый код должен быть понятен по именам и структуре; сложная логика — в отдельные функции с тестами и, при необходимости, docstring.

---

## 3. Запрет глобальных переменных — закон

- **Запрещено:**
  - объявлять изменяемое глобальное состояние (модульные переменные, которые переприсваиваются или мутируются);
  - использовать ключевое слово `global` для изменения переменных.
- **Разрешено:**
  - константы в `UPPER_SNAKE_CASE` в `app.core.constants` (или аналог) — только неизменяемые значения (строки, числа, кортежи);
  - `TypeVar`, `ParamSpec` на уровне модуля для типизации.
- Зависимости и состояние — только через **Dependency Injection** (контейнеры в `app.core.containers`, `Depends()` в FastAPI). Никаких синглтонов «через модуль» вне DI.

---

## 4. Всё должно быть обложено тестами

- **Новый код:** для каждой новой функции/метода/эндпоинта — соответствующие unit-тесты (и при необходимости integration/e2e).
- **Изменённый код:** при изменении поведения — обновить или добавить тесты так, чтобы новое поведение было зафиксировано.
- **Структура тестов:** см. `docs/testing.md`. Использовать data-driven подход: сущности и ожидания в `tests/schemas/`, `@pytest.mark.parametrize`, явные `id` для сценариев.
- **Покрытие:** проект настроен на `fail_under = 95%`. Не снижать покрытие; новые ветки кода должны быть покрыты.
- **Запуск перед коммитом:** минимум `make run.unit.cov` (unit + coverage). При изменении API — прогон `pytest tests/e2e` или эквивалент.

---

## 5. Линтеры и типизация обязательны

- **Ruff:** перед завершением правок выполнять `make ruff.check` и `make ruff.format`. Код должен проходить все включённые правила (см. `pyproject.toml`).
- **mypy:** выполнять `make mypy.check`. Строгий режим (`strict = true`). Не добавлять необоснованные `# type: ignore`.
- **Порядок:** после правок — сначала Ruff, потом mypy, затем тесты. Не коммитить код, не прошедший эти проверки.

---

## 6. Архитектура и стиль кода

- **Clean Architecture:** зависимости только «внутрь»: Presentation → Application → Domain; Infrastructure реализует интерфейсы из Domain. Не тащить инфраструктурные детали в Domain/Application.
- **Импорты:** только абсолютные (first-party как `app.*`). Запрет относительных импортов (настроено в Ruff).
- **Типизация:** аннотации типов обязательны для всех публичных функций и методов; `from __future__ import annotations` в модулях с аннотациями.
- **Именование:** модули — `snake_case`, классы — `PascalCase`, интерфейсы — префикс `I` (например, `ISearchRepository`). Соответствовать `docs/structure.md` и `pyproject.toml` (naming, docstrings).

---

## 7. Конфигурация и секреты

- Конфигурация — через **Dynaconf** и файлы в `configs/` (`settings.toml`, `.secrets.toml`, `.env`). Не хардкодить секреты и окружение в коде.
- Пути к конфигам — только из `app.core.constants`. Не размазывать `os.getenv`/`os.environ` по коду; читать настройки через централизованную загрузку.

---

## 8. Чек-лист перед завершением правки

- [ ] Линтер: `make ruff.check` и `make ruff.format` — без ошибок.
- [ ] Типы: `make mypy.check` — без ошибок.
- [ ] Тесты: `make run.unit.cov` — зелёные, покрытие не ниже порога.
- [ ] Нет новых глобальных изменяемых переменных; зависимость — только через DI.
- [ ] Публичные контракты не сломаны; при изменении API — тесты обновлены/добавлены.
- [ ] Изменения минимальны (LEAN), без лишнего рефакторинга и мертвого кода.
