# Стандарт ведения коммитов

Мы используем соглашение [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) для обеспечения читаемости истории изменений и автоматизации процессов (версионирование, changelog).

## Неприкосновенные правила качества (в т.ч. для агентов)

- **Запрещено подавлять проверки в коде**: `# noqa`, `# type: ignore` и аналоги недопустимы.
- **Запрещено самовольно добавлять игноры в `pyproject.toml`** (например `extend-per-file-ignores`, `ignore` и т.п.).
- **Любая проблема должна решаться**, а не скрываться подавлением линтера/типов.

## Формат сообщения

Сообщение коммита должно иметь следующую структуру:

```
<тип>[необязательный контекст]: <описание>

[необязательное тело сообщения]

[необязательный нижний колонтитул]
```

## Типы (Types)

Используйте следующие типы для описания изменений:

| Тип | Описание |
|-----|----------|
| **feat** | Новая функциональность (feature). |
| **fix** | Исправление ошибки (bug fix). |
| **docs** | Изменения только в документации. |
| **style** | Изменения, не влияющие на выполнение кода (пробелы, форматирование, пропущенные точки с запятой и т.д.). |
| **refactor** | Изменение кода, которое не исправляет баг и не добавляет новую функциональность. |
| **perf** | Изменение кода, повышающее производительность. |
| **test** | Добавление недостающих тестов или исправление существующих. |
| **build** | Изменения, влияющие на систему сборки или внешние зависимости (примеры: pip, docker, npm). |
| **ci** | Изменения файлов конфигурации и скриптов CI (примеры: GitLab CI, GitHub Actions). |
| **chore** | Прочие изменения, не изменяющие src или supply файлы (например, обновление .gitignore). |
| **revert** | Откат предыдущего коммита. |

## Примеры

### Feature

```
feat(auth): добавить поддержку OAuth2 авторизации
```

### Fix

```
fix(db): исправить некорректный запрос при фильтрации пользователей
```

### Breaking Change

```
feat(api): изменить формат ответа endpoint /users

BREAKING CHANGE: поле `fullname` заменено на `first_name` и `last_name`
```

## Инструменты контроля

Для автоматической проверки сообщений коммитов используется **commitizen** и **pre-commit** хуки. Перед коммитом убедитесь, что ваше сообщение соответствует стандарту.

Установка хуков:

```bash
pre-commit install
pre-commit install --hook-type commit-msg
```
